## 1. Problem setting and the paper it is anchored to

The Sod shock tube (Sod 1978, "A survey of several finite difference methods for
systems of nonlinear hyperbolic conservation laws", J. Comput. Phys. 27, 1-31) is
the 1-D Riemann problem for the Euler equations

    (rho, u, p) = (1.0, 0.0, 1.0)     x < x0 = 0.5
    (rho, u, p) = (0.125, 0.0, 0.1)   x > x0,        gamma = 1.4, x in [0,1]

whose solution at time t consists of four waves: a left-going centred rarefaction
(head/tail), a contact discontinuity and a right-going shock. The published
reference values for this state (as tabulated in Toro 2009, Ch. 4, for exactly
this problem) are `p* = 0.30313`, `u* = 0.92745`,
`rho*_L = 0.42632`, `rho*_R = 0.26557` with wave speeds
`S_head = -1.18322`, `S_tail = -0.07042`,
`S_contact = 0.92745`, `S_shock = 1.75216`.

**Deviation declared.** The mission fixes the output time at **t = 0.14**; the
profiles printed in Sod (1978) fig. 3 / Toro (2009) fig. 4.7 are drawn at
**t = 0.2**. The exact solution is self-similar in `xi = (x-x0)/t`, so the star
state is time invariant and only the positions scale (`x = x0 + S t`); the
reproduction is therefore graded at t = 0.14 and, in addition, a t = 0.2 run is
reported so the figure can be compared with the published one directly
(`artifacts/sod_profiles_t0.2_paper_time.png`). No paper PDF was re-parsed in this
run: the reference numbers are the published star state, and they are themselves
cross-checked against two independent exact solvers (section 4).

## 2. Method and implementation

* Solver: existing `tensorfvm.compressible` surface — `EulerSolver`
  (`src/tensorfvm/compressible/solver.py`), MUSCL-Hancock reconstruction with a
  monotonised-central limiter + HLLC flux (`src/tensorfvm/compressible/riemann.py`),
  CFL = 0.4, outflow boundaries, `ny = 1` with periodic `y`. Order 1 = donor cell.
* Case: `cases.sod(nx, order=..., limiter=..., t_end=...)`
  (`src/tensorfvm/compressible/cases.py:96`), integration by `solver.run(t_end)`.
* Reference: an own NumPy exact Riemann solver (bisection on the Toro pressure
  function, `_pressure_function`/`exact_star_state` in
  `src/tensorfvm/verification/sod1978.py`) so the grading reference never comes
  from the code being graded; `reference_cross_check()` also compares it with
  `ExactRiemann` and with the published values.
* Measurements (`wave_positions`, `star_plateaus`): the rarefaction edges are a
  straight line fitted to the fan interior (`u` is linear in `xi` there) and
  extrapolated to `u = 0` (head) and `u = u*` (tail); contact and shock are
  half-level `rho` crossings between the adjacent plateaus, linearly interpolated
  inside the straddling cell. Star values are means over the central 50 % of each
  plateau, so the smeared edges do not enter them.
* L1 error: `mean_i |q_i - q_exact(x_i,t)|`; the control experiment repeats it
  with the exact *cell average* (16 sub-cells per cell) so that the sampling
  choice cannot be blamed for the observed rate.

Observed orders on the Sod solution: order 1 → 0.617, 0.651, 0.660; order 2 → 0.977, 0.894, 0.857.
Control experiment (exact cell averages instead of cell-centre sampling):
order 1 → 0.589, 0.653, 0.669; order 2 → 0.871, 0.917, 0.927 — the rate is unchanged, so the sub-unity rate
is not a sampling artefact. Design order on the smooth periodic entropy wave
(`rho = 1 + 0.2 sin(2 pi x)`, u = 0.5, p = 1, periodic, t = 0.2): order 1 → 0.994, 0.997, 0.999;
order 2 → 2.132, 2.096, 2.045, i.e. 1.0 and 2.0 within the declared 2 % band. This is the
standard attribution: a TVD/shock-capturing scheme diffuses the contact and the
fan edges, so its L1 rate across discontinuities is bounded near one (a
first-order upwind scheme diffuses a moving contact over `sqrt(nu t) ~ sqrt(h)`,
which is the 0.5-0.7 seen here), while its design order is intact on smooth data.

## 6. Failure modes, artifacts, reproduction

* **Honest FAIL**: `C3_sod_l1_order_ge_1_literal = false` (0.66 / 0.86 < 1).
  `fail_stage = "criterion C3 (literal L1 order on the discontinuous solution)"`,
  `failure_reason = "a TVD/shock-capturing scheme cannot exceed L1 order ~1 across
  the Sod discontinuities; the criterion as specified is not achievable and is
  mis-specified for a shock tube. The scheme's design order (1.00 / 2.05) is
  certified on smooth data instead; the cell-averaged control rules out a
  measurement artefact."` Next round should re-specify C3 as a design-order test
  (smooth case) or a weak-norm/position-error test.
* Other failure modes seen: the first-order fan-tail estimator is biased by the
  (physical) fan smearing — at nx = 400 it lands 0.72 cell (0.365 %) right of the
  exact tail, at nx = 100 it is 3.6 cells off; the order-2 measurement is used for
  grading for that reason, and every grid is reported. If xi = x (instead of x/t)
  is passed to `ExactRiemann.sample`, the profile is silently wrong — this is the
  friction entry 4 below.
* Artifacts: `artifacts/sod1978_t0.14.json` (all numbers, verdicts, friction),
  `artifacts/sod_profiles_t0.14.png` (rho,u,p vs exact, both orders),
  `artifacts/sod_convergence.png` (L1 vs h for Sod and for the smooth wave),
  `artifacts/sod_criteria_margins.png` (criterion margins),
  `artifacts/sod_profiles_t0.2_paper_time.png` (published-figure time).
* Reproduction: `python scripts/repro_fvm_sod1978.py --out docs/repro-fvm-sod1978`
  (about 4 minutes; exit code 1 because of the honest C3 FAIL). Gate:

## 7. Ecosystem friction and debugging findings

Two real defects were found in the existing compressible surface and fixed
(regression tests in `tests/test_compressible_eos_riemann.py`):

1. **`ExactRiemann.density_star_l/r` applied the Hugoniot unconditionally.** In
   the Sod problem the left wave is a rarefaction, so
   `rho*_L = rho_L (p*/p_L)^(1/gamma) = 0.42632`; the accessor returned the
   post-shock value `0.44720` (**+4.9 %**), and the star sound speed built from it
   moved the fan tail from -0.07042 to -0.04670 (**33.7 %**). `sample()` was
   already correct (`torch.where(is_shock, ...)`), so the accessor and the sampled
   solution disagreed with each other. Fixed by selecting the isentropic branch
   when `p* <= p_k`; after the fix the accessor matches the published value to
   0.0001 %.
2. **"Reflected wave speed" was always the shock branch.** `cases.bubble_analytic`
   reported `reflected_is_rarefaction = true` and, in the same dict, the speed of
   a *shock* (-0.77226 where the rarefaction head is -0.86890, **11 %** off).
   Added `ExactRiemann.wave_speed_l/r` (shock speed for a shock, fan head for a
   rarefaction) and switched the three metadata uses to it; shock cases are
   unchanged (Richtmyer-Meshkov `reflected_shock_speed` still -0.7151350).

Overall: the compressible path is numerically sound (C1/C2 pass with one to three
orders of margin, conservation drift at round-off, design order intact), the
anchor is trustworthy (two independent exact solvers agree with the published

mis-specified criterion and an API that makes the self-similarity coordinate and
the wave-family branch easy to get wrong.
