# VOF transport stencil: verification audit (von Neumann + exact benchmarks)

Verification-debt audit of `tensorfvm.two_phase_vof.VOFTransport`, generated by `python -m tensorfvm.verification.vof_transport_audit`.

## 1. Case description

`VOFTransport.advect` blends donor and acceptor face values with the Courant number as weight: `f = f_donor + C (f_acceptor - f_donor)`. Its docstring claims a "donor-cell (CICSAM-like)" scheme that is stable and bounded for CFL <= 1. This audit checks that claim at three levels: (i) the discrete symbol of the implemented stencil, (ii) the modified-equation diffusion coefficient against textbook theory, (iii) two periodic benchmarks with exact solutions (one full period of smooth advection; Zalesak slotted-disc rigid-body rotation on the unit square). All runs are float64, CPU, single rank.

## 2. Method

| item | setting |
|---|---|
| 1D probe grid | n = 256, Fourier mode m = 4 (theta = pi/32), amplitude 0.35 about 0.5 |
| symbol measurement | per-step amplification from FFT of a single mode, |G| = (|X^N|/|X^0|)^(1/N) |
| diffusion | D = -ln|G|/(C theta^2), least-squares extrapolation in theta^2 -> 0 |
| 1D convergence | 1 period of u = 1 advection, C = 0.25, n = 32/64/128/256 |
| Zalesak | unit square, r = 0.15 at (0.5, 0.75), slot 0.05 x 0.10, omega = 1, T = 2 pi |
| Zalesak grids | n = 64 / 128 / 256, CFL = 0.25 (and 0.5 for the default scheme) |
| periodic driver | transcribes `VOFTransport.advect` face by face (donor/acceptor, pure pinning, [0,1] clip); equivalence to the library class is a pytest gate |

## 6. Notes, limitations, applicability

1. The default (`blend`) scheme is *not* donor-cell: with C as the blend weight it is pure upwind at C = 0, central differencing at C = 0.5 and pure downwind at C = 1. Its stability limit is C = 1/3, so the documented "bounded for CFL <= 1" is wrong for smooth fields.
2. The [0, 1] clip plus pure-donor pinning act as a hard limiter: they keep the solution in range on sharp interfaces (which is why the existing interface tests pass) but they are exactly the mechanism that breaks geometric conservation when the linear growth would exceed the bounds.
3. `TwoPhaseSolver.vof_cfl_limit = 0.5` sits inside the unstable band; either use `scheme='upwind'` (added here, opt-in, default unchanged) or cap the VOF Courant number at <= 1/3.
4. This audit says nothing about 3D or about the two-phase coupling; it bounds the transport operator only. Interface reconstruction (PLIC) remains unimplemented.
