# three_point 壁面闭合：从「静默死代码」到可机检的二阶闭合（并诚实保留 O(1) 高原）

## ① 案例介绍

TensorFVM 原生三维黏性算子 `NativeViscous3D` 在 Dirichlet（壁面）面上需要壁面法向梯度。
默认 `wall_closure='two_point'` 用两点差分，其 Taylor 展开缺 `(δ/2)∂²u/∂n²`，
因此壁面牵引只有一阶精度，壁邻单元散度在 `tests/test_native_viscous_order3d.py`
里被记录为 **O(1) 高原**（一条 `xfail(strict=True)` 挂在那里）。

同一文件已经实现了第二条闭合路径 `wall_closure='three_point'`（三个点：壁面面心、
owner 单元中心、沿面法向的第二单元中心，一维三点单边差分），文档声明它
「对仿射场精确、对光滑场二阶」，并把「升级面数」暴露为 `wall_second_order_faces`。

物理背景（为什么关心壁邻单元散度）：不可压 FVM 的壁面摩擦阻力完全由壁面切向牵引积分给出，
壁面法向梯度若只有一阶，壁面牵引与壁邻单元的动量收支会随网格加密**不再改善**；
工程后果是壁面剪切/阻力收敛性不可证。

几何/参数：
* 计算域：单位立方体 `hex_box(n)`，`n³` 六面体；`triangulate_faces` 决定面是四边形（面心在
  单元中心连线上）还是切成两个三角形（面心为三角形形心，偏离连线）。
* 黏度 μ = 1.3（与既有阶次研究同口径），制造解流场
  `u=(sin(πx)cos(πy/2)e^z, cos(πx/2)sin(πy)e^{-z}, sin(πx)sin(πy)z)`，
  另有二次场 `p·A·p + p·b`（用于闭合算子自身的精确性判据）。
* 网格层级 n = 4, 6, 8, 12；隐式求解用 `scipy.sparse.linalg.spsolve`。

## ② 怎么做的

1. **先审计、后动手**：`grep -rn three_point` 在全仓只命中 `src/tensorfvm/native_viscous3d.py`
   自身——**没有任何测试、没有任何调用点**。把它打开跑一次，得到的流场与 `two_point`
   **逐位相同**，`wall_second_order_faces = 0`。
2. **定位两个堆叠缺陷**（第二个被第一个掩盖）：
   * 定向错误：`_assemble_three_point_wall` 用 `align = sig*(gn·nf)` 判定第二单元是否
     「沿法向」，但仓内边界面法向是**朝外**的（owner 中心在 −n 侧），于是
     `align ≤ −1 < 0.5` 全部被拒；后续 `delta0 = (cc−fc)·nf < 0` 的守卫同样按「法向朝内」
     的约定写成。整块代码是按「边界法向朝内」写的，实际网格是朝外 ⇒ 静默空转。
   * 装配形状错误：一旦有面被升级，`drop` 用 `nc[bd][mask]`（形如 `(n_up, N)` 的整行）
     去配 `np.tile(np.arange(3), len(fb))` 的列索引，长度不等 → `ValueError`。
     升级面为空时两者长度同为 0，所以第一个缺陷把第二个完全掩盖了 π。
3. **最小修复**（`src/tensorfvm/native_viscous3d.py`）：
   * 对齐判据改为沿「face → owner 中心」方向（与法向定向无关）；
   * 守卫改为「第二单元与 owner 同侧且更远」；
   * 三点权重的符号用 `side = sign(δ0)` 归一，恢复朝外法向下的正确导数符号；
   * `drop` 改写成稀疏形式 `diags(n·ê_k · upgraded) @ nc`（`nc` 为法向收缩算子），不再展开成稠密矩阵；
   * 新增**共线守卫** `_COLLINEAR_TOL=1e-6`：面心偏离单元中心连线（三角形面）时不升级，
     保持 two_point，避免「升级了反而退化成非仿射精确」。
4. **机检化**：新增 `tests/test_native_viscous_wall_closure3d.py`（9 个用例），把
   ①激活计数 ②仿射精确 ③二次法向导数精确 ④三角形面回退 ⑤定分辨率解题误差收益
   ⑥高原**未被**治愈，全部钉成断言。
5. **可复现产物**：`scripts/audit_wall_closure3d.py` 一次跑出 `audit.json` 与两张图，
   本文所有数字都由该脚本写入，无手抄。

## ⑤ 注意点

* **本修复不治愈高原**。壁邻单元散度仍是 O(1)（`l2_wall` 在 3.2–3.8 间摆动，斜率 ≈ 0.1），
  `tests/test_native_viscous_order3d.py::test_wall_cell_divergence_must_be_second_order`
  的 strict xfail **保持红灯**（本单跑测仍是 1 xfailed，未粉饰）。
  也就是说：文档里「二阶」的声明在**面法向导数**这一层成立（9e-15），
  在**壁邻单元散度**这一层不成立——后者还受面值重构和网格几何支配。
* **三角形面会退回 two_point**。`hex_box` 默认 `triangulate_faces=True`，面心是三角形形心，
  偏离单元中心连线约 0.47·|δ|，一维三点权重在这类节点上不仿射精确
  （实测仿射牵引误差 9.6e-3，二次法向误差 0.99）。共线守卫把这类面全部挡回 two_point，
  保证「闭合永不劣化」；代价是：凡面被三角化，本闭合不生效。
  `verification/native_order3d.hex_box(..., triangulate_faces=False)`、
  `verification/native_hybrid_flow.channel_mesh(..., triangulate_faces=False)` 上是生效的。
* **阶仍约 1**。两种闭合的解 l2 斜率都收敛到 ~1.1（不是 2）。说明当前网格族（无论面是否三角化）
  的**主误差源不在壁面闭合**：内点截断斜率同样只有 ~1.18，指向面值/梯度重构与单元几何，
  这是比壁面闭合更大的一笔欠账（本轮未触碰）。
* 三次收敛级 n=12 仍然粗（制造解含 e^{±z}、π 波数，h·k ≈ 0.26），斜率在 0.66–1.12 间非单调，
  不能声称渐近阶；表中斜率仅作趋势记录。
* 修复只影响 `wall_closure='three_point'` 分支；默认 `two_point` 的数值路径未变（对比表第一列与
  历史记录 3.3483/3.3420/3.0230（三角形面）逐位一致）。

## ⑥ 误差判定（是否 <3%）

| 关键量 | 基准 | 误差 | <3%? |
|---|---|---|---|
| 修复后仿射牵引（three_point，四边形面） | 解析 μs·grad | 8.2e-16（绝对，量级 O(1)） | ✅ 是 |
| 修复后二次场法向导数 | 解析 ∂u/∂n | 9.1e-15（绝对，量级 O(1)） | ✅ 是 |
| 未修复版本的激活面数 | 应为 216 | 0（100% 空转） | ❌ 否（已修） |
| three_point 解题 l2 相对场标度（n=12） | 自身解析场 | 4.0e-3/49.9 = 0.008% | ✅ 是 |
| three_point 解题 l2 相对 two_point（同网格） | two_point | −28%…−33%（比值 0.672–0.720，单调） | ✅ 改善 |
| 壁邻单元散度误差 / 场标度（n=12） | 解析 div τ | 3.18/49.9 = **6.4%**，且不随加密下降 | ❌ **否**（honest FAIL，如实保留） |
| 解 l2 收敛阶 | 理论 2 | 实测 ~1.1（n=4..12） | ❌ 否（欠账转移至内点重构） |

结论一句话：**把一个从未运行过的功能变成「可运行 + 可机检 + 二阶于法向导数 + 永不劣化」，
同时用同一套断言证明它并没有治好 O(1) 高原**——欠账没有被掩盖，只是被定位得更准。
