# CASE-FVM-CHANNEL-KMM180 —— 无闭合路线「管到底」诊断：能否发展出雷诺剪应力？

> **重开·TensorFVM#777·管到底第2轮**（m22266）。本诊断回答一个决定性的问题：
> 无闭合（closure-free）路线 `src/tensorfvm/verification/channel_spectral_dns.py`
> 在 `Re_tau=180` 槽道里**能否发展出湍流**（即能否让 `uv_plus` 从 $O(10^{-6})$ 长到
> 满足准入判据 C1 的份额），从而把 m20573 判定的 **VACUOUS_PASS** 修成 **ADMISSIBLE**。
> 结论：**不能**——该求解器在可用的分辨率下把初始扰动衰减回层流，雷诺剪应力始终为零，
> 因此无闭合路线的 PASS 在物理上不成立（falsified hypothesis）。

## 1. 背景与判据

`docs/case-fvm-channel-kmm180-dns` 报出的无闭合 `u+(y+)` 在 legacy 窗口 1.61 %、
物理对数层 2.59 %（均 < 5 % 判据）——但 m20573 审计判定该 PASS 为 **vacuous**：
同一批工件里 `uv_plus` 为 $O(10^{-6})$、动量平衡残差 0.708 $u_\tau^2$（占施加剪切 87 %），
即该状态不是动量方程的解，而是几乎未演化的初始条件。

预注册准入判据（`kmm180_closurefree_audit.CRITERIA`，审计前冻结）：

| id | 量 | 限 |
|---|---|---|
| C1 | 对数层内解析雷诺剪应力份额 `-<u'v'>+/(1-Y/h)` | >= 0.50 |
| C2 | 动量平衡残差 `|du+/dy+ - <u'v'>+ - (1-Y/h)|` | <= 0.05 |
| C3 | 统计窗口（流向流通时间） | >= 1.00 |

**本诊断的问题**：C1 是硬门槛——若求解器根本长不出雷诺剪应力，则无论跑多久、
无论 `u+` 与 DNS 多接近，PASS 都只能是 vacuous。因此「管到底」必须先回答：
**这个求解器能不能发展出湍流？**

## 2. 怎么做的

对 `SpectralChannel`（流向/展向 Fourier + 壁法向交错有限体积 + SSP-RK3 + Strang 分裂）
在多个分辨率下做**长时程扰动演化诊断**：从 `blended` 复合律初始剖面加 15–50 % 随机扰动
（`noise=0.5, seed=11`）出发，逐时间步推进，每若干步用 `StatisticsAccumulator` 采样
`(x,z,t)` 平均，折叠上下半槽后读取对数层（$y^+\in[30,36]$）的
`-<u'v'>+/(1-Y/h)` 份额、`uv_plus` 峰值、`u_{rms}^+` 与体积平均 `U_b^+`。

关键观测量：
- **`uv_share_log`**：对数层内雷诺剪应力占施加剪切的份额（C1 的直接量）；
- **`uv_max`**：全剖面 `uv_plus` 峰值（若为 $O(10^{-6})$ 即无湍流）；
- **`u_rms`**：流向脉动强度（初始扰动是增长还是衰减）；
- **`bulk`**：体积平均 `U_b^+`（无雷诺应力时在体积力下持续加速，是"未达平衡"的指示）。

## 4. 结论（误差判定）

| 关键量 | 观测 | 基准（C1 门槛） | 是否达标 |
|---|---|---|---|
| 对数层 `uv_share_log`（16x64x16） | 0.000 | >= 0.50 | **否** |
| 对数层 `uv_share_log`（32x128x32） | 0.000 | >= 0.50 | **否** |
| 对数层 `uv_share_log`（64x128x64，已发布） | < 1e-3 | >= 0.50 | **否** |
| `uv_max`（全部网格） | $O(10^{-4}\to10^{-6})$ | 需 $O(1)$ | **否** |
| `u_rms^+` 演化 | 0.5 → 0.14（衰减） | 需增长 | **否** |

**显式回答**：无闭合路线在 16x64x16、32x128x32、64x128x64 三个分辨率下，
初始扰动**全部衰减**（`u_rms^+` 单调下降），雷诺剪应力**始终为零**（`uv_share_log` ≈ 0），
体积平均速度在体积力下**持续加速**（`U_b^+` 从 15.25 升向 16.91，未达平衡）。
**C1 判据在任何可运行的分辨率下都不满足**——这不是"跑得不够久"或"窗口太短"，
而是该求解器在可用网格下**无法维持湍流**（欠分辨 + 数值耗散把扰动抹平）。

因此：m20573 判定的 **VACUOUS_PASS 无法通过加长/加密修复**。无闭合路线的
`u+` 与 DNS 的 1.61 %/2.59 % 接近是**初始条件**（`blended` 复合律）与 DNS 的巧合，
不是求解器收敛的证据。该路线作为 KMM180 锚点的离散验证证据**不成立**（falsified）。

## 5. 注意点与局限

- **本诊断的局限**：只测到 64x128x64（原分辨率）。更细的网格（如 128x256x128，
  dx+=8.8）理论上更接近壁面分辨 DNS，但本诊断的粗/中网格已显示**扰动单调衰减**的
  一致模式，且更细网格的计算成本（4.2M 单元 × 数万步）远超本单可承受范围；
  若后续有资源可再验证，但当前证据不支持"加密即可修复"的假设。
- **物理原因**：`Re_tau=180` 的 Kolmogorov 尺度 $\eta^+\approx 5$ 壁面单位，
  而 64x128x64 网格 $\Delta x^+=18$、$\Delta z^+=9$ 远大于它——小尺度湍流未被解析，
  数值耗散把扰动抹平。这是**欠分辨无闭合**（under-resolved, no model）的固有局限，
  不是可修的 bug。
- **与 RANS 路线的关系**：本诊断只撤回无闭合路线的 PASS，不改变 RANS 路线
  （`docs/oss_solutions/CASE-FVM-CHANNEL-KMM180.json`）在物理对数层的 FAIL 结论——
  那个 FAIL 由 `nu_t` 闭合承担，与本诊断无关。
