## 1. Contract / intended behaviour

Anchor `CASE-HEATED-CAVITY-FVM` = natural convection in a differentially heated square
cavity, Pr = 0.71, Ra ∈ {10³, 10⁴, 10⁵, 10⁶}, hot left wall, adiabatic top/bottom.
Acceptance = mean Nusselt number (and velocity extrema) against de Vahl Davis (1983),
Int. J. Numer. Methods Fluids 3:249-264, Tables 2-3; the code gate in
`tests/test_fvm_internal_flow_verified.py:158` is **3 %**, the owner standard rejects
**>15 %**. Platform benchmark row: `tensor_benchmark_cases WHERE anchor_slug='CASE-HEATED-CAVITY-FVM'`.

## 2. Method of this audit

1. Read the diff (`git show b16f518f`), the solver path
   (`src/tensorfvm/internal_flow/natural_convection.py`, `reference.py`) and the driver
   (`scripts/run_cavity_case.py`, `scripts/assemble_cavity_benchmark.py`).

   for m15410.
5. Ran the delivered tests and added the missing ledger regression test.

## 4. Findings (severity-ranked)

Blocking: **none**. The declared capability is real.

| id | sev | finding |
|---|---|---|
| P1 | medium | `tensor_benchmark_cases` had **no row** for `CASE-HEATED-CAVITY-FVM` — the campaign had an anchor and a verdict but no registered criterion, so no machine judge existed for it (only `CASE-CAVITY-RE1000-FVM`, the lid-driven case). Audit registered the row (ref_source = paper Tables 2-3, tolerance = 3 % code gate / 15 % platform limit). |
| P2 | medium | `scripts/make_report.py:73-85` **hand-types** the result tables — violates the zero-handcopy rule; the report would not move if the ledger changed. |
| P3 | medium | Report `tensor_reports#14620` figures carry `name`+`caption` only; `png_base64` is **absent** for all 4 figures → report element ④ is metadata only. |
| P4 | low | Report §6 quotes a `<5 %` band and never answers the mandatory "是否 <3 %" (answer would have been yes: max 1.15 %). |
| P5 | low | `artifacts/heated-cavity-benchmark/` was left **untracked** (`git status: ?? artifacts/`) although commit `b16f518f` claims "Add … artifacts"; evidence existed only in the mission work tree. Audit archived it to `docs/audit-m15410-heated-cavity/original-artifacts/`. |
| P6 | medium | No executing test covered the deliverable: `tests/test_fvm_internal_flow_verified.py::test_cavity_nusselt_against_de_vahl_davis` **skips** (needs `benchmarks/verified/fvm_natural_convection/summary.json`, absent in a plain checkout); the other two tests only check the reference dicts and the second-order wall gradient. Audit added `tests/test_heated_cavity_benchmark_ledger.py` (6 tests, 0.16 s). |
| P7 | low | `src/tensorfvm/internal_flow/mac.py:589 streamfunction()` is the open-channel form (cumsum of u anchored at the bottom wall). Pre-existing, does not touch Nu/u_max/v_max (those come from θ and `cell_velocity`). |
| P8 | low | `src/tensorfvm/internal_flow/reference.py` on `main`/eco checkout still carries the **stale** anchors (`Ra=1e3 Nu=1.334`, `Ra=1e4 u_max=4.535/v_max=6.776`); the fix lives only on `agent/m15410`. Until merged, downstream `study.py`/`sweep.py` consumers keep the wrong anchors. |

Overstated claims: the commit message's "Add … artifacts" (see P5) and the `<5 %` framing
instead of the true and stronger `<3 %` (see P4).

## 5. Level verdict

**L4 — 基准验证（完整算例 + 误差分析 + 可复现）**, not L5.
Reasons: real code path (StaggeredMAC + Boussinesq energy) → entry → artifacts; the
capability is integrated (the `NaturalConvectionCase` wrapper is used by
`internal_flow/study.py`, `sweep.py`, `maturation.py`); full 4-Rayleigh case set with
mesh-convergence error analysis; independent re-run reproduces the ledger bit-identically;
external literature anchor met at ≤1.15 % for every metric.
Not L5 because m15410 added no new capability or physics (the solver module predates it),
and the automated-regression / criterion-registration gaps (P1, P6) are below L5 standard.

## 6. Disposition

**Approve with notes.** The measured deliverable is genuine and reproducible; the defects
are bookkeeping/reporting (P1-P6, all closed or documented by this audit) plus two
pre-existing upstream issues (P7 streamfunction diagnostic, P8 stale anchors on main) that
should be picked up as separate small missions. Nothing was re-implemented here.
