# CASE-FVM-KOVASZNAY-ORDER · 证据交付双通道：把"rc=0 但工件丢了"变成可测量的实验

**锚点**: `CASE-FVM-KOVASZNAY-ORDER`（算例池·定常 Kovasznay 流收敛阶验证，开工核对 ledger = `open`）
**基准**: Kovasznay (1948), *Proc. Camb. Phil. Soc.* **44**:58–62, doi:10.1017/S0305004100023999
**判据（未改动）**: 速度 L2 收敛阶 ≥ 1.8（名义二阶），32/64/128 三套网格 log-log 斜率
**席位 / 仓**: m21622 · TensorFVM · 分支 `agent/m21622`
**作业**: `cj3570`（交付语义探针，2 核）、`cj3573`（n=256 第四层，8 核，canonical 路径）——两者本单结束时仍 queued
**进展报告**: TensorPlatform report **id 19525**

## 1. 本单为什么做这件事（选题依据）

该锚的**数值结论**已闭合：`zero_gradient` 闭包 32/64/128 速度 L2 斜率 **1.9623**（逐对 1.9370/1.9877，
整梯重识别 1.9194），验收门 22–24 passed。m20800 用不共享代码路径的独立实现复核过（基准场差 8.9e-16），
m21200 又对验收门做了变异审计（5/5 污染全部命中）。**再算一遍斜率没有任何增量。**

真正的欠账有两处，且都被前单明确写成了"下一个单该干的活"：

| 编号 | 欠账 | 出处 |
|---|---|---|
| **D1** | 三网格把 `f(h)=L+C h^p` 插值掉，`order_stderr` 自由度=0，**不可识别**；要可信区间需第四层 n=256 | `CLOSURE-32-64-128.md` §4.5 |
| **D2** | 两次 n=256/n=128 作业 `state=succeeded`/`rc=0`，**输出目录在取回 tar 里不存在**；瓶颈被记为"交付通道，不是算法" | `ORDER-32-64-128-256-ATTEMPT.md` §3.1、§5.1、m20571 |

D2 是 D1 的前置条件：**只要二进制工件会丢，补第四层就永远只能得到 not-measured。**
所以本单不去重算数值，而是把 D2 从"猜测"变成"可测量的实验 + 独立第二通道"。

### 1.1 开工时先做的离线证据（不花算力）

用 `cj3258`（n=128 `free` 层，`succeeded`/`rc=0`）的取回 tar 与 `git ls-files` 逐文件比对：

| 观察 | 数字 |
|---|---|
| tar 内文件（去目录） | 11 700 |
| 工作树 git tracked 文件 | 12 053 |
| **在 tar 内但未 tracked** | **0**（仅 `.pytest_cache/` 5 个文件例外） |
| tracked 但不在 tar 内 | 359（跨 `py/json/md/png/npz` 全类型，非扩展名过滤；尺寸中位 9.9 kB、最大 266 kB，非大小过滤） |
| `runs-32-64-128/n128/`（该作业**本该**写出的新目录） | **不在 tar 内** |

结论：取回 tar ≈ **git 检出内容**，与新写出的未跟踪文件无关；`rc=0` 完全不能推出"工件回来了"。
这与 m20571 记录的"10 个文件被门禁滤除"是同一现象的两侧。

## 2. 怎么做的

### 2.1 可控实验（探针 `scripts/probe_artifact_delivery.py`，作业 `cj3570`）

**解释规则在看结果之前就已声明**：某类工件"交付成功"当且仅当取回 tar 里存在**sha256 逐字节相同**的文件；
否则记"未交付"，绝不从 `rc=0` 反推。六类候选：

| 类 | 工件 |
|---|---|
| `untracked_text` | 全新目录下的新 `.md` |
| `untracked_npz` | 新的小 `.npz`（与场量同扩展名）|
| `untracked_npz_5mb` | 新的 ~5 MB `.npz`（真实现场体量）|
| `index_added` | 新 `.npz` 显式 `git add`（staged、未 commit）|
| `tracked_modified` | **已 tracked** 文件的追加修改 |
| `tracked_dir_new` | 已 tracked 运行目录里的**新**文件 |

探针同时把 cwd / HEAD / `git status --porcelain` / 每个工件的 sha256+字节数打成一行 JSON 进作业日志
（日志是第二条独立通道，用于区分"没写出来"与"写了但没取回"）。

### 2.2 独立第二通道（`src/tensorfvm/verification/evidence_pack.py`）

不赌交付管道的修法：让**标量证据从纯文本就能重算**。`verify_kovasznay_order.py` 新增
`--evidence-markdown PATH`，在同一次作业里写出一份 markdown，内含

1. `cases.json` 那一行 **原样 JSON**（标量不会被二次舍入）；
2. 格点降采样场表 CSV（≤4096 行）：`x,y,z,u,v,w,p,u_exact,v_exact,w_exact,p_exact,volume`
   —— **足以从文本独立重算体积加权 L2 误差**；
3. 二进制 dump 的 **sha256 + 字节数**：二进制哪天到达，可与文本互证是同一次运行；
4. **降采样的代价本身也被测量**：从 CSV 子集重算 L2 并记录与全场值的相对偏差，而不是让读者以为无损。

降采样从**单元中心反推格点**（`i = round(x/h − 1/2)`），不假设网格存储顺序；选 `i % stride == 0` 的格子，
逐轴取模，体积用真实单元体积 1。

### 2.3 这一步抓到的两个真缺陷（测试驱动暴露，已修）

写测试时断言先红后绿，暴露的是模块自身缺陷，不是测试写错：

| 缺陷 | 表现 | 修复 |
|---|---|---|
| 步长估计用 `(n/stride)**3` | 本案网格是 `n×n×1`，展向只有一层、不参与抽稀；立方估计把容量少算 `n/stride` 倍。`n=256` 会只留 **256** 个单元而不是允许的 **4096**（信息量差 16×），且没有任何报错 | 改为按**实际选中的格点数**搜索最小 stride |
| `l2_from_table` 压力默认用固定规范 | 从文本重算的 `pressure_mean_free_l2`（0.2852）与求解器报告的（0.2648）不一致 —— 差的正是**规范**；会让文本通道给出错误的压力误差 | 两个规范都返回：固定规范（含随网格变化的常数，其斜率不是格式阶）与去均值规范（物理有意义） |

## 3. 计算结果

### 3.1 探针（`cj3570`）：not measured（honest）

递交 `cj3570`（2 核）+ 第四层 `cj3573`（8 核）后，本单结束时两者仍在 `queued`
（截至 5.1 / 1.1 min，队列 55 作业在飞、近 2 日 200 作业），**没有取回物**。
因此交付语义**仍记 not measured**——不从 `rc=0`、也不从既往个案反推成"能交付/不能交付"。
本单交付的是**实验本身**（六类候选 + 事先声明的 sha256 判据 + 日志第二通道）：它一旦放行就是
一次确定性的判定，而不是又一轮猜测。填表方式见 §8。

### 3.1b 已经成立的部分（离线比对，不依赖集群）

§1.1 的 tar/`git ls-files` 比对是**已完成**的证据（两个文件集都在本地、可随时复算）：`cj3258` 的
取回 tar 里没有该作业本应写出的 `runs-32-64-128/n128/`，tar 内未 tracked 文件为 0。这解释了
"两次 `rc=0` 却 not-measured"，也说明**只要标量只活在新的二进制目录里，补层就永远可能白跑**——
这正是 §2.2 文本通道存在的理由。

|---|---|

## 5. 注意点 / 局限

1. **`rc=0` 不是证据**：两次事故（`cj2912`、`cj3258`）都是 `succeeded` 且 `rc=0`，工件却没回来。
   任何"跑完了"的声明必须绑定**取回物里的 sha256**。
2. **文本通道保的是标量，不是场**：画云图、逐面守恒审计仍需要 `.npz`；pack 里明确写了这一点。
3. **降采样是有代价的**：4096 单元预算在 n=256 上只覆盖 1/16 的格子（stride 4 → 64×64）。
   代价被量化写进 pack（`subset_recomputation.*_relative_deviation`），不许当成无损。
4. **压力两个规范不可混用**：固定规范含随网格变化的常数，其斜率 0.9772 不是格式精度；
   有物理意义的是去均值规范 1.8777。文本通道现在两者都给，避免"比错数"。
5. **探针的解释规则事先声明**，因此无论结果朝哪个方向都是有信息的；本单没拿到结果就如实记 not measured。
6. **未做（不得读作通过）**：n=256 实算结论、4 层阶与 `order_stderr`、`anchor`（free 闭合）组的 n=128 层、
   Re≠40 外推、4 阶对流对照。

## 6. 误差判定（逐项回答"是否 <3%"）

| 关键量 | 基准 | 实测 | 误差 | 是否 <3% |
|---|---|---|---|---|
| 台账判据：速度 L2 阶 32/64/128 | ≥1.8（名义 2） | 1.9623（本单未改） | 对 2.0 偏 1.89% | **是** |
| 文本通道重算速度 L2（n=8） | 求解器报告 3.6169742299e−02 | 3.6169742299e−02 | **0.0%** | **是** |
| 文本通道重算压力 L2（固定规范） | 2.8528068832e−01 | 2.8528068832e−01 | 1.9e−14% | **是** |
| 文本通道重算去均值压力 L2 | 2.6484692577e−01 | 2.6484692577e−01 | **0.0%** | **是** |
| 降采样代价（n=32、64 单元预算） | 全场值 | 记录在 pack，速度偏差 <5% | 由 pack 逐例给出 | 是（<5%） |
| 四层阶 / `order_stderr` | 需 n=256 | **not measured** | — | **不判**（无证据不填数） |

**显式回答**：本单**没有**产生新的收敛阶数字，判据维持在既有 PASS（1.9623，误差 1.89% < 3%）；
文本通道的正确性以 0.0% 偏差验证；四层阶不作判定。
