**席位**: m20800（selfstart, tp-ds-4）· **仓**: TensorFVM · **日期**: 2026-11-14
**基准**: Kovasznay, L. I. G. (1948), *Proc. Camb. Phil. Soc.* **44**:58–62, doi:10.1017/s0305004100023999

## 1. 为什么要做这一单（现门的两个循环依赖）

`closeout-32-64-128.md` / `RESULT_32_64_128.md`（m20239）已把判据做到 PASS：速度 L2 三网格
log-log 斜率 1.9623、去均值压力 1.8777，`tests/test_kovasznay_32_64_128_acceptance.py` 22 passed。
但那一套门在**证据生成链**上有两处自我引用，验收数字再绿也无法排除：

1. **同一份误差被当成两份**：门标榜"从 npz 现场重算"，但重算调用的是生产方用的那个
   `tensorfvm.native_manufactured3d.volume_weighted_error`。若该函数口径有误（归一化、
   体积权重、分量求和），生产与验收会同错同对，`requested == recomputed` 永远成立。
   它实际证明的只是"没有手抄"。
2. **基准场被信任而非被检验**：门直接读 npz 里的 `exact_velocity` / `exact_pressure`。
   若这两个数组来自错误的 Re、错误的 λ 符号或拟合场，整条链仍然完全可复现。
   判据原文要求"目标数值任务从 ref 原文查得"，所以基准必须能被独立重建。

本单因此是对**已合并成果的验证欠账**：不改求解器、不改判据，只在旁边装一条**不共享代码路径**
的复核。结论先给：判据成立，两条路径差 4.9e-13。

## 2. 怎么做的（独立实现，零 TensorFVM import）

`scripts/verify_kovasznay_reference_independent.py`（新增，纯 numpy）：

1. **λ 双路求根**：闭式 `λ=(Re−√(Re²+4(2π)²))/2` 与 `[-5,0]` 上二分求 `λ²−Reλ=(2π)²`
   互相校验（差 >1e−12 直接 SystemExit）。得 λ = -0.9637405441957689，
   恒等式残差 8.53e-14。
2. **证明重建场真是定常 N–S 解**：在 8 个随机内点上用四阶中心差分算 div u 与两条动量方程残差，
   而不是"相信公式"。div 最大 3.87e-12，动量残差最大 9.32e-08
   （量级即四阶差分截断，h=2e−5）。
3. **比对已提交的基准数组**：把重建场在每层 npz 的 `cell_centers` 上取值，与 npz 的
   `exact_velocity` / `exact_pressure` 逐点相减（压力允许一个常数规范）。
4. **独立重算误差与斜率**：自写体积加权相对 L2（含去均值规范）与自写最小二乘 log-log 拟合，
   再与 `summary.json` 已发布的 `fits`/`verdict` 对账。
5. **Richardson / GCI 与采样偏差阶**：判据只要求"斜率 ≥1.8"，但三点拟合本身也需要一个不确定度；
   同时确认单元中心采样的 O(h²) 截断不会把斜率掰弯。

### 3.4 误差预算与不确定度

* 单元中心采样偏差（速度）：['6.555e-04', '1.639e-04', '4.099e-05']，其自身阶
  **1.9997** —— 是 O(h²) 截断，与离散误差同阶收敛，**不会污染斜率**（若它是 O(h)，

  压力 7.99e-04；

## 4. 判定（逐项回答"是否 <3%"）

| 量 | 基准 | 结果 | 误差 | 是否达标 |
|---|---|---|---|---|
| 速度 L2 收敛阶 | 判据 1.8（名义二阶 2） | 1.9623（独立路径同值） | 对名义二阶偏 1.88% | **是** |
| 去均值压力 L2 收敛阶 | 判据 1.8 | 1.8777 | 对 1.8 阈值的裕度 4.32% | **是**（裕度小，见 §5.2） |

| 重建场是否满足 N–S | 解析残差 0 | 9.3e-08（FD 截断） | — | **是** |
| 采样偏差是否污染斜率 | 需 O(h²) | 阶 1.9997 | 对 2 偏 0.02% | **是** |

## 5. 注意点 / 局限

1. **本单复核的是"基准 + 度量 + 斜率"，不是"离散解本身"**：输入仍是同一批 npz 场，
   若求解器把场写错而 cases.json 也跟着错，本单看不见。要堵这一层需另起一条独立离散化
   （如谱方法/不同库）做交叉求解，超出本单范围。
2. **去均值压力的裕度只有 4.32%**：这是三个点的统计量，任何一层
   轻微退化都可能把它压到阈值下。若后续要收紧结论，应补 n=256 层而不是重算同一层。
3. **固定规范压力阶（0.9772）不是精度量度**，本单同样不采用：动量方程只定压力梯度，
   固定规范下压力随网格变动的常数偏差会伪装成"一阶"。
4. **伪展向份额的斜率（1.456）无物理意义**（绝对值 6.8e−18…9.0e−19，纯舍入抖动），
   本单只把它当误差预算记录，不当收敛率。
5. **GCI 用的是三点 LSQ 阶 + Roache Fs=1.25**，属工程惯例的保守因子，不是严格上界。

## 7. 附：`free` 闭合序列（验收门的 `anchor` 组）补齐进展

验收门的三组证据里，`anchor`（历史 `free` 牵引自由闭合）一直只有 n=32，n=64/n=128 是
诚实的 not-measured。本单把这两层递到集群：

| 作业 | 内容 | 结果 |
|---|---|---|
| **cj2958** | `free`, n=64 | **成功**，工件已入树 `runs-32-64-128/n64/`（21 次外迭代收敛，solve 479.4 s） |
| cj2959 | `free`, n=128 | 递交后 60 min 仍在跑，工件未落盘 → 仍记 not-measured（不猜、不补） |

n=64 实测（`cases.json`，可由 npz 复算）：

| 量 | 值 |
|---|---|
| velocity L2 (全 3D) | 1.217236e-03 |
| pressure L2 (固定规范) | 3.949543e-02 |
| pressure L2 (去均值) | 7.986706e-03 |
| max&#124;w&#124;（伪展向） | 2.195687e-03 |
| 外迭代 / 动量残差 | 21 / 9.16e-10 |

**关键发现（新缺陷，阻断该序列的拟合）**：`summarize_kovasznay_32_64_128.py::validate_levels`
拒绝把本层并入序列，理由

```
n=64 was solved with a different configuration (reference n=32): {'symmetry_closure': (None, 'free')}
```

即历史 n=32 的 `cases.json` 里 **没有** `symmetry_closure` 字段（None），
而新生产的 n=64 记为 `'free'`。两者物理配置相同，但证据元数据 schema 漂移让一致性门把
"未记录"判成"不同"。这与 `m20571-artifact-schema-drift-diagnosis.md` 是同一类缺陷，
但此处后果不同：它**只**影响 `free` 组的补层，不影响验收判据（判据口径是 `zero_gradient`）。

闭合该组有两条路，都不该在本单偷偷做：

1. **用当前生产脚本重跑 n=32 free**（同配置，实测量级 ~2 min）使三层元数据同源 —— 代价是
   覆盖已提交的历史工件；
2. **修门**：把 `None` 解释为"未记录"而非"不同"，并在并入时补写实际闭合方式 —— 需要
   一个独立小单，因为它触及证据一致性门的语义（宁可保守失败，也不该被随手放宽）。

本单选择**不动门、不动历史工件**，如实记录：`anchor` 组仍为 not-measured（n=128 未落盘 +
n=32 元数据漂移），验收判据不受影响。

另注：n=64 free 的 max&#124;w&#124; = 2.196e-03，是 O(h) 伪展向模态的实证
（zero_gradient 同层为 2.5e−17）。这就是为什么判据只在 `zero_gradient` 口径上度量全 3D 范数。
