# CASE-FVM-DAMBREAK-STOKER · 数值配置认证包络（CFL / 阶数 / 干床深度下限）

**锚点**: `CASE-FVM-DAMBREAK-STOKER`（TensorFVM 浅水算例池；总账开工核对 `status = open`）· mission 22998 · 分支 `agent/m22998`
**参考**: Ritter (1892) *Z. Ver. Deutsch. Ing.* **36**, 947-954；Stoker (1957) *Water Waves* ch. 10；
Toro (2009) *Riemann Solvers* 3rd ed. ch. 6；池条目 `docs/oss_solutions/CASE-FVM-DAMBREAK-STOKER.json`
**容差**: 池口径 `< 5 %`（`TOLERANCE = 0.05`，未改）；池接受网格下限 `ACCEPTED_MIN_N = 800`
**工件**: `docs/case-fvm-dambreak-stoker-config-envelope/`（`metrics.json`、`SUMMARY.md`、`proposed_pool_amendment.json`、4 张 png；数字全部由 `scripts/run_dambreak_config_envelope.py` 程序化注入）
**判定**: **锚点 PASS 在 CFL 与阶数轴上稳健（全扫描带 8/8、2/2 通过，零硬失效）**；**在深度下限轴上不稳健**——
`front_wetted<5%` 在 `dry_depth = 1e-6` 就破（池网格 n=1600 上 6.64 %），而该量在出厂默认 `1e-12` 下只有 **1.7× 余量**。
故池条目必须声明 `dry_depth`，否则 PASS 不可复现。

## ① 案例介绍（为什么这条轴值得扫）

池条目把浅水求解器在**一个**数值配置点上的读数当作「格式的性质」发布：
`n = 1600`、`cfl = 0.4`、`order = 2`、以及 `ShallowWater1D` 出厂默认的**绝对深度下限** `dry_depth = 1e-12` m。
前三个是显式声明过的，第四个从来没有被当作参数：它既不在池条目里，也不在任何既有研究里被**变化**过
（`shallow_water.robustness` 扫的是物理不变性——平移/边界/域长/相似缩比——不是数值参数）。

而 `dry_depth` 不是装饰性容差。求解器在五处读它：

| 位置 | 作用 |
|---|---|
| `set_state` | `h <= dry_depth` 的格子把 `hu` 置 0 |
| `primitive` | 「干」格子的速度**定义**为 0 |
| `_face_states` | 重构速度在 `h <= dry_depth` 处置 0 |
| `_hll_flux` | 两侧都在下限以下的面上通量置 0（`dry_pair`） |
| `_sanitise` | 下限以下格子里的残余 `hu` 每级丢弃（`dry_flips` 计数） |

也就是说：**干床波前的被测速度场是由下限定义的**——一个 `h` 低于下限的格子报 `u = 0`，而解析解在那里
是 `u -> 2 c0`。这正是锚点速度腿那条 open honest-FAIL（`u`-L1 = 5.07 % @ n=800）所量的东西；
本单的回答是：**其中多少是下限约定、多少是格式误差**，可按下限扫描直接分开。

算例参数（锚点原样，未改一行）：`g = 9.81 m/s²`，`h0 = 1.0 m`，湿床 `h1 = 0.5 m`，坝址 `x = 0`，
域 `[-4, 6] m`，`t* = t√(g h0)/h0 = 2`（`t = 0.638551 s`，`x_f = 4.0 m`，水跃 `x = 1.888781 m`）。

## ② 怎么做的

1. **只加一个透传参数**。`dam_break.run_case(..., dry_depth=1e-12)` 把下限交给 `ShallowWater1D`，并把它写进
   `discretisation` 记录。默认值 = 求解器默认值，因此**池条目已发布的每个数字逐位不变**
   （`tests/test_dambreak_config_envelope.py::test_default_floor_is_the_solver_default_and_reproduces_the_pool_numbers` 钉住）。
   求解器、精确解、池门（`_verdict`）一行未改。
2. **三条单因子轴**（`verification.dambreak_config_envelope`）：
   CFL ∈ {0.1,0.2,0.3,0.4,0.6,0.8,0.9,0.95}（后者贴着显式稳定极限）、阶数 ∈ {1,2}、
   下限 ∈ {1e-15,1e-12,1e-9,1e-6,1e-4,1e-3,1e-2,5e-2}（`1e-15` 是「没有下限」的探针，`5e-2` 用于**括出失效端**——
   一个从不离开认证区的扫描无法定位边界）。扫描在 `n = 800`（= 池接受下限）做，关键点在 `n = 1600`（池网格）确认。
3. **硬失效门（池门表达不了的东西）**：异常、正值裁剪格数（`clipped_cells`、`dry_flips`）、质量漂移
   （> 1e-12 判泄漏）、非有限的读数、未定义的读数（NaN 不能当通过）。CFL 逼近 1 时格式真正的死法是
   负水深被静默截断（质量泄漏），而这种失效不会以「百分比」出现。
4. **新仪器 + 标定**：`floor_diagnostics` 从返回的剖面上读「不公正干燥」——数值 `h <= floor` 而解析 `h > floor`
   的格子、其中藏的水量、以及几何尺子 `3 t √(g·floor)`（Ritter 扇区 `h = (2c0−xi)²/(9g)` 在 `xi = 2c0 − 3√(g eps)`
   处达到 `eps`）。仪器本身对着 2^18 点求积做标定，并给出**有效域**（见 ③ 表 5）。
5. **负对照**：故意把下限设到所有解析水深之上（干床 0.5 m / 湿床 0.6 m），要求扫描器**必须**看见坏配置
   （NaN 读数 + 3 个伪极值 + 深度 L1 16.1 % / 水跃 13.0 %）。绿的列只有在能变红时才有意义。

## ⑤ 注意点（踩过的坑 / 局限）

1. **湿边后退不是几何阈值效应**。若下限只是「读数阈值」，后退量应等于 `3t√(g·floor)`；实测大 1–4 个数量级
   （floor 1e-9：几何 1.9e-4 m vs 实测 0.194 m ≈ 1000×）。故下限**改的是动力学**（薄层的动量/面通量被截断），
   不只是读数。扣除「无下限也不消失」的本征后退（floor=1e-15 时 0.031 m ≈ 2.5 格），
   下限驱动的部分 `R−R₀` 对几何薄层长度的 log–log 斜率 ≈ **0.35**（4.7 个数量级内），
   **这是经验律，只在一条网格族上测过，不给机理结论**。
2. **本征后退本身不随 n 收敛**：0.0625 / 0.106 / 0.116 m @ n=400/800/1600（≈5 / 8.5 / 18.5 格）——
   近似**固定物理长度 ~0.1 m**，这正是 `front_wetted` 的 1.6 %→2.89 %「不收敛」的来源，
   也让该量在 5 % 门上的通过带有「出厂下限足够小」的运气成分。7 年前的已知诊断，本单首次给出量化斜率。
3. **`dry_flips` 是每步累计的事件计数**（n=400 基线 684 次），不是格数：它告诉你「下限在前沿每步都在介入」，
   不能读成「有多少格被错误干燥」。
4. **池门不是精度门**：一阶格式以 5× 差的误差同样全绿（表 3）。引用池条目只能说「≤5 % 带宽内通过」。
5. **未做（not_run）**：二维/斜置溃坝的同一轴；`t* > 2` 长时程与下限的耦合；异族代码交叉；
   湿床在 `h1 < floor` 的退化区（本单湿床扫描的下限全部远低于 `h1 = 0.5`，仅负对照 0.6 越界）。

## ⑥ 误差判定（关键量 vs 基准，逐项回答「是否 <3%」）

| 量 | 基准 | 实测 | 网格 | 相对误差 | <3 % ? |
|---|---|---|---|---|---|
| 干床波前 `x_f`（fan 估计器） | 4.000000 m（Ritter） | 4.000690 m | n=1600 | 1.726e-4 | **是** |
| 干床湿边 `x_f`（legacy 口径） | 4.000000 m | 3.884375 m | n=1600 | 2.891e-2 | 是（仅 1.7× 余量，且由下限决定） |
| 湿床水跃位置 | 1.888781 m（Stoker） | 1.889598 m | n=800 | 4.33e-4 | **是** |
| 湿床水位阶跃 `h2/h1` | 1.453840892 | 1.453838 | n=800 | 2.13e-6 | **是** |
| 深度剖面 L1（干 / 湿） | 闭式 | 7.72e-4 / 8.51e-4 | n=1600 / n=800 | 见左 | **是** |
| `x_f(t)` 序列最大误差 | 闭式 | 4.25e-3 | n=1600 | 4.25e-3 | **是** |
| 波形单调性 | 内部极值 = 0 | 0 | n=1600 | — | **是** |
| （轴外判定）湿边 vs 下限 | — | floor=1e-6 → 6.64e-2 | n=1600 | 6.64e-2 | **否**（超出 5 % 门） |

**结论一句话**：锚点在**声明的配置**下，两条 headline（干床波前、湿床水跃）与深度/阶跃/序列/单调性各判据
全部 <0.005（其中 headline <0.03 %），远优于 5 % 门；唯一「只差 1.7 倍」的是 legacy 湿边读数 2.89 %，
而它正是下限的读数——把下限从出厂 `1e-12` 抬到 `1e-6` 就变成 6.64 % 破门（8/8 → 7/8）。
因此池条目应把数值配置（`n, cfl, order, dry_depth`）与认证带（`dry_depth ≤ 1e-9`、`cfl ∈ [0.1, 0.95]`、`order ∈ {1,2}`）
一起发布——`proposed_pool_amendment.json` 是可直接合入的机器可读版本。

> 口径提示：上表湿床两行的「实测」值由 `SHOCK_POSITION` 类读数给出（`metrics.json` 的 `reading` 段），
> 干床湿边的时间样本取自同一次运行；未测的量一律留空，不用估算值填充。
