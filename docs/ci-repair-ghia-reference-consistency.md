# CI repair for PR #132 (branch `agent/m4036` → merged into `agent/m4108`)

## 1. Symptom

PR #132 added the Ghia reference-consistency audit package
(`src/tensorfvm/verification/ghia_reference_audit.py`,
`scripts/audit_ghia_reference_consistency.py`,
`docs/verification-ghia-reference-consistency/`, tests). Its CI was red on
`test (3.11)`, `test (3.12)` and `lint (advisory)`.

## 2. Root cause of the test jobs

`scripts/audit_ghia_reference_consistency.py --check` re-rendered the whole
package into a temporary directory and compared the two figures with

```python
os.path.getsize(committed) != os.path.getsize(fresh)
```

i.e. **PNG byte-length equality**. That is a property of the rasteriser, not of
the data:

* the committed figures embed the build that produced them — their `tEXt`
  chunk is `Software = Matplotlib version3.10.8, https://matplotlib.org/`, so a
  different Matplotlib patch release alone rewrites the file;
* glyph rasterisation and line antialiasing come from the runner's
  freetype/harfbuzz, which differs between the dev box and `ubuntu-latest`.

Reproduced locally on the same record without touching any number, by only
changing a font-hinting switch (the closest available stand-in for a different
freetype build):

| rendering of the identical record | `profile.png` bytes | geometry |
|---|---|---|
| default rc | 142 840 | 1844 × 990 |
| `text.hinting = "no_hinting"` | 148 003 | 1844 × 990 |
| `font.size = 9.0` | 139 742 | 1844 × 990 |

The test `test_the_package_re_renders_bit_identically` therefore failed on any
runner that was not the authoring box, which is why both Python versions went
red together.

## 3. Fix (minimal, no numbers touched)

`scripts/audit_ghia_reference_consistency.py`

* new `_png_geometry()` parses the IHDR chunk (signature + `struct`) and returns
  `(width, height)`;
* `--check` still diffs `results.json` and `report.md` **byte for byte** (that is
  where every number lives), but compares the figures by geometry, and reports a
  missing/corrupt PNG as a failure instead of a crash;
* module docstring and the generated `report.md` state why raster bytes are not
  compared.

`tests/test_ghia_reference_consistency_audit.py`

* `test_the_package_re_renders_bit_identically` →
  `test_the_package_re_renders_from_its_own_record` (same assertion, honest name);
* new checks that the relaxed comparison still has teeth:
  * `test_figure_bytes_follow_the_rasteriser_while_the_data_does_not` — pins the
    portability argument, and asserts `results.json` stays byte-identical while
    the PNG size moves;
  * `test_re_render_check_notices_a_figure_of_the_wrong_geometry` — a wrong-sized
    figure makes `--check` exit 1;
  * `test_re_render_check_notices_a_hand_edited_number` — one edited number in
    `report.md` makes `--check` exit 1;
  * `test_re_render_check_refuses_a_non_png_artefact` — a non-PNG makes `--check`
    exit 1.

`docs/verification-ghia-reference-consistency/{report.md,results.json}` were
regenerated by the script; the two PNGs are unchanged (byte-identical, same
renderer here).

## 5. What is **not** fixed: `lint (advisory)`

That job fails on `main` itself, not because of this PR:

* `ruff format --check src tests scripts` → **567 of 569 files** would be
  reformatted, including files this PR never touches;
* `ruff check src tests scripts` → 9 841 findings (semicolon-packed statements,
  unused imports) — the pre-existing backlog that the workflow itself documents
  as the reason the job is advisory;
* the two pre-existing files this PR edits are already unformatted on `main`
  (`ruff format --check` on their `origin/main` copies: *2 files would be
  reformatted*).

Reformatting the tree is exactly the "unrelated file" churn this task forbids,
so the advisory job is left as it was: it fails identically before and after this
branch, and it cannot block the merge (`continue-on-error: true`).
